# 删除进回收站（state/trash/），直删只留作 EXDEV 回退

> 正文代价段的「其三，没有恢复 UI」已随 2026-09-26 的「修订」段作废：恢复端点（`GET/POST /api/trash`）与界面入口（世界线屏回收站视图 + 一键恢复）都已上线。正文保留当时的论据，**最新口径以文末「修订」为准**（范式同 ADR-0020）。

世界线的「删除」原来是 `fs.rmSync` 整目录直删、画廊素材是 `fs.unlinkSync` 单文件直删：一局几十轮的 state/summary/story-tree 与全部 history 快照、或引擎画出来的立绘/背景，点两下确认就不可逆地没了——个人项目没有服务端备份与版本历史，误删的代价全部落在玩家（常常就是开发者自己）身上。裁决：删除一律先挪进 `state/trash/`（`moveToTrash(root, ...rel)`，server 内唯一入口），项命名 `<删除时间戳ms>-<随机4字符>-<原名>/`（随机后缀规避同一原名反复删除的撞名），世界线目录与素材文件同款。选 rename 而非复制后删除：同卷 rename 原子，要么整体进 trash、要么原样不动，不存在「删了一半」的中间态；trash 长在 `state/` 下，天然不在任何扫描面内（`scanPresets`/`scanPresetAudio`/`listAssets` 只看 `presets/`，`listWorlds` 与快照只看 `worlds/` 与 `index.json`，`migrateLegacyState` 只读 state/ 本层 `*.md`），挪进去的东西等于从游戏里消失，不需要各扫描点逐一排除。**回收站是尽力而为**：跨设备挂载（EXDEV）等 rename 失败时回退 `rmSync` 直删并在返回值里带 `fallback:"purged"` 标记——删除操作本身不能因为 trash 失败而失败，宁可丢回收站也不能丢「删除」语义（回退的 rmSync 也失败则原样抛出，交给调用方按删除失败报 500）。恢复只走手工文档（`state/README.md`「回收站」一节：世界线目录挪回 `state/worlds/<id>/` 并在 `index.json` 手工补条目，素材剥掉 trash 前缀挪回 `presets/<id>/assets/`）。代价：其一，磁盘占用只增不减（**不自动清理、不设上限**，回收站纪律交给玩家手动管理——自动清退必然引入「保留几天」这类拍脑袋参数，且清错一次就回到了直删）；其二，世界线恢复要手工补 index.json 条目（索引是唯一列表真源，删除时先移除条目再挪目录，两步无法对随手恢复做增量索引）；其三，没有恢复 UI（`existsSync` 语义、删除确认文案、世界线列表都以「删掉即消失」为前提，恢复 UI 要引入按类型剥前缀、索引回补、重名冲突三套规则，超出「误删有后悔药」这个最小诉求）。客户端只在删除成功的提示文案里说明去向（「已移入回收站（state/trash/ 可手工找回）」），交互不变。被否决：继续直删（误删不可逆）、复制后删源（两步之间崩溃会留下双份或半份）、trash 放进 `state/worlds/` 下靠扫描排除（每个读 worlds 的点都要记得排除，漏一处就「幽灵世界」）、自动过期清理（见上）。

## 修订（2026-09-26）：回收站恢复 UI 上线，「没有恢复 UI」一条作废

**触发**：正文代价段的「其三，没有恢复 UI」把恢复锁在手工文档（`state/README.md` 一节）里。实际使用暴露了两件事：① 回收站里躺着的东西**玩家看得到却点不动**——世界线屏删除成功只留一句「可手工找回」，而 `state/trash/` 要玩家自己去文件系统里翻；② 恢复的两类条目（世界线目录 / 素材文件）本就各有明确的落点，手工恢复里唯一麻烦的「世界线要把索引条目补回去」在服务端是**读一下就写回**的事，不该外包给玩家。当初列的三套规则（按类型剥前缀、索引回补、重名冲突）不是不需要，而是现在有地方放它们了。

**新语义：两个端点 + 一个界面入口。** 服务端在 `worlds.mjs` 出 `listTrash(root)` 与 `restoreTrash(root, id)`，路由 `GET /api/trash`（→ `{entries:[{id, kind:"world"|"asset", name, presetId?, at}]}`）与 `POST /api/trash {action:"restore", id}`（→ `{ok}`）。两类条目的判定与恢复动作在服务端收口（客户端只渲染、只点）：

- **世界线目录**：恢复回 `state/worlds/<worldId>/`，并**回补索引条目**——`preset` 从 trash 内 `state.md` 的 `- preset: <id>` 读、`chapterNo` 从 `story-tree.md` 读；目录名与索引 `worldId` 一致是这条路径的前提（删除时就是这么挪的，前缀是唯一变量）。
- **素材文件**：剥掉 trash 前缀（含 `<剧本id>` 段）还原成原名，挪回 `presets/<剧本 id>/assets/<原名>`；`presetId` 标注让跨剧本同名素材不会串味。

界面入口在世界线屏（回收站视图列表 + 一键恢复）。**重名冲突**仍在服务端防：恢复目标已存在时不覆盖（按类型给一句人话）。**`state/README.md` 的手工恢复一节保留**——它是服务不可用/手工修盘时的最后一条路，只是从「唯一的路」降级为「兜底的路」。

**没变的**：删除仍一律先进 `state/trash/`、EXDEV 仍回退直删并标 `fallback:"purged"`、**仍不自动清理、不设上限**（那两条是本裁决的核心，恢复 UI 不改变「后悔药由玩家手动管理」这个取舍）；`moveToTrash` 仍是删除侧的**唯一入口**，`restoreTrash` 是恢复侧的。**代价**：`worlds.mjs` 多两个导出与它们的索引回补逻辑、`routes.mjs` 多两个端点、世界线屏多一个视图（连同它的空态与错误态）、`state/README.md` 与本文档的措辞要跟着改口径（「只走手工文档」不再成立）；恢复是**破坏性动作**（会在 `worlds/` 或 `assets/` 里落地文件），所以入口与删除同款纪律——两段确认、忙碌期不恢复。被否决：**只给素材恢复、不给世界线恢复**（丢一局才是大头）；**恢复时自动改名躲重名**（玩家要的是「把它弄回来」，不是「弄回来一份 -2」，且改名后索引还得跟着改）；**把恢复做成 `state/trash/` 的文件浏览器**（那等于把内部目录结构摊给玩家，与裸 worldId 不上屏同一条纪律）。
