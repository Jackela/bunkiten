# 回合原文日志（logs/）+ 缺选项段的质量守卫追问

正戏回合的叙事原文只活在 server 内存：`turnText` 随 chunk 累积、回合结束、下次 `sendPrompt` 清空——引擎某轮胡言乱语或漏协议段，事后无从回溯「它到底说了什么」；逐轮快照（ADR-0009）只存三文件全文，回答不了这个问题。同时每轮协议要求每回合带 `**行动**` 选项段，引擎偶尔忘写：玩家没有选项只能自由输入（客户端 FreeInput 可用，体验降级但不算崩坏）。裁决分两半。

其一，**回合原文日志**：`state/worlds/<worldId>/logs/NNNN.json`（与 history/ 平级），条目 `{seq,at,prompt,text}`——「发了什么 + 引擎回了什么」。写入时机与判定和逐轮快照完全同一处（`sendPrompt` 内 `flushArtLines()` 之后、`busy=false` 之前，`isMainTurn(prompt) && currentWorldId`），但它是**独立条目流**：append-only、不清理、4 位补零、seq>9999 与快照同款截断；快照去重（三文件全等）的回合**日志照写**——日志记叙事原文，与三文件去重是两回事。seq 尽量与同回合快照对齐（`writeSnapshot` 的返回，ok 与 duplicate 分支都带 seq），对齐值追不上 logs 自己的进度时（快照去重、restore 的 backup 只进 history）退回 logs 的 max+1：append-only 永不让步、任何路径不覆盖既有文件——logs 的定位是「按时间读原文」，不是与 history 的 join key。**不进世界线导出包**（exportWorld 只读三文件与 history/）：日志是本机排障面，不是可迁移的档，导入侧的引擎没有这段历史，带着它只会让新世界时间线自相矛盾；fork 也不复制（新世界自己的回合自己记）；无读取端点（排查直接看文件）。

其二，**质量守卫**：上述判定点之前（`flushArtLines()` 与快照/日志落盘之间），正戏回合的 `turnText` 缺 `**行动**` → 在**同一 busy 窗口内**自动补发一条内部追问 `SUPPLEMENT_PROMPT`（`server/protocol-lines.mjs`，以「补充：」开头，只要求补发完整的每轮协议回合尾、不重述正文）。追问复用 acp 会话再发一次 `session/prompt`：chunks 流进同一 `turnText`，客户端看到同一回合的补全（SSE 照常流，零 client 改动），省一次 `turn_end`；追问不另写快照与日志条目（日志 `text` 自然含补全后全文）；走 `EFFORT_PLANNING` 低档（它不在指令前缀集，`pickEffort` 会给正戏档，故显式指定，`lastEffort` 记账、下回合自动拉回）。**每回合至多一次**（单次判定、无重试循环）：追问后仍缺 `**行动**` 或追问本身失败（引擎 error/超时）都放弃，回合照常成功收尾、日志留痕（text 缺选项段即证据）——守卫是纠错不是门禁，不能因为补丁失败把一回合好的叙事判死。追问的 session/prompt 走独立的 120s 超时（只要回合尾，不必占满主回合 600s 的预算），超时与引擎 error 同路：warn 后放弃，不转 409。章末回合豁免：`turnText` 命中 `CHAPTER_MARK_RE`（`shared/protocol.mjs` 的章标记正则真源）时不追问——输出 `【章】第 N 章 完` 的回合是每轮协议「以选项结束」的唯一合法例外（SKILL【章节与剧情树】明文该轮不再出选项），缺 `**行动**` 不是引擎忘写。边界：`SUPPLEMENT_PROMPT` 是 server→引擎的内部指令，**不进 `shared/protocol.mjs`**、不进 RULES 六句（追问是客户端纠错行为非常驻纪律；SKILL「每轮协议」第 5 条让引擎知情：收到「补充：」不是玩家输入）。

代价：其一，logs 只增不减（与 history 同款取舍，磁盘换可回溯性；上限 9999 条兜底）；其二，快照去重/backup 之后 logs 与 history 的 seq 会永久错位一档（见上，按时间读不受影响，按 seq join 会踩坑——文档明示）；其三，追问会把引擎多留一次请求的延迟摊进少数回合（正常回合零开销）；其四，日志原文含剧透（明文本机落盘，与 state.md 同级敏感度，不额外加密）。被否决：log 进导出包（时间线自相矛盾）、按 seq 强对齐并允许覆盖（破坏 append-only）、追问走独立 turn_end（客户端要区分「补全回合」与「新回合」，状态机复杂化）、追问重试 N 次（错误格式的引擎多问也补不上，反而拖慢收尾）、把「补充：」加进 DIRECTIVE_PREFIX_RE（那会同时改掉档位与正戏判定的语义面，牵连契约 lint ⑥）。
