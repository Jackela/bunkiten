# 快照条目记玩家输入（存档点重演），去重与导出包随动

「重演」从 v1.7 起就有（撤销刚结束的正戏回合并重发同一输入，命令轨「进度 ▾」菜单的「重演这一幕」），但输入只活在内存账本 `lastTurnPrompt` 里：刷新/重启后账本为空、重演永久不可用；而且它天然只认最新一回合，没有任何办法重演更早的某一幕。盘上其实有输入——`logs/NNNN.json` 的 `prompt`——但 logs 没有读取端点，且它的 seq 与 history 因去重/backup/指令回合而**已知会错位**：正常路径 1:1，快照去重让 logs 多、`restore` 的 backup 让 history 多，指令回合两边都不写。要按 seq 把「存档点 #12 ↔ 那条输入」拼起来，就得在服务端实现并维护一条「猜对齐」规则——把已知会错位的东西做成契约。

本裁决把输入**放进快照条目本身**：`history/NNNN.json` 加 `prompt`（`writeTurnSnapshot` 传 `isDirectivePrompt(text) ? "" : text`：只记玩家叙事输入；客户端的开局/续玩指令回填空串——它们是客户端生成的指令、不是玩家的话，重演入口对空输入给降级提示；引擎侧原文仍在 logs 的 `prompt`，两处口径不同、各有其用）。输入与其产生的状态同条目绑定，去重/backup/续玩/指令回合那堆错位一次性消失；`normalizeSnapshot` 仍是唯一形状入口（旧档缺字段 → 收敛为空串，降级提示而非报错）。解析规则：目标幕 K —— 游戏屏 = 最近一条**带玩家输入**的 turn 条目（刷新/重启后的「继续世界线」、回退后的重同步都会落一条 prompt 为空的续玩条目，要往回找，`REPLAY_PROBE_MAX`=8 条上限兜极端链），剧情图屏 = 玩家点的那一条（出现条件 `canReplaySnapshot`：是 turn 条目、且它之前还有 turn 条目）—— 回退点 T = K 之前最近的一条 `kind:"turn"` 条目（`prevTurnSnapshotSeq`，两个纯函数都在 `src/lib/replay.ts`，两个入口共用一份规则）→ 复用既有 restore + 重同步 + 排队重发时序（`pendingRerollPrompt` 的排队语义不变）。客户端随之删掉 `lastTurnPrompt` 与 `pendingTurnPrompt` 两个内存账本字段——刷新后照样可重演。

**去重语义随动**：从「与上一条 files 全等则跳过」改为「files 全等**且这次没有新的玩家输入**（`prompt` 为空或与上一条相同）才跳过」。理由：一条快照值得落盘的判据是「世界变了，或玩家说了新的话」——files 相同但输入不同 = 新的一幕（「最新带输入的 turn 条目 ⟺ 最新一幕」的不变量靠它；v1.13 之前无状态变化的回合不落条目，重演会退早一幕），空输入的读档回合只有真改了文件才落盘（读档不该留噪声条目）。写盘代价：一次比较多一个字段。

**导出包随动**：快照条目进包时带 `prompt`（`exportWorld` 的显式映射，存档自洽——换台机器导入回来也能重演），`WORLD_BUNDLE_VERSION` 2 → 3：形态变更显式步进版本号，不为「旧版应用会不会拒收」扭曲语义（旧版整包拒收属版本闸的正常行为；v1/v2 包照收、缺字段的条目 normalize 为 `""`）。代价如实记下：**玩家当时说的话随包外流**（以前只在本机 logs 里）。顺带修一处同源债：客户端 `parseWorldBundle` 的版本闸把上限抄成「只认 v1」（v1.8 起 v2 包在应用内导入会被本地挡下、服务端明明已收），改为「version 是正整数」，上限由服务端裁决。

**读取面分层不变**：列表 `/api/history`（不带 seq）继续只回元信息——不带 `files` 也不带 `prompt`，历史抽屉/剧情图标注这些高频只读面不为重演付流量；单条 `?seq=` 才带（`{...entry}` spread 天然涵盖，服务端零改动），重演入口「点击时解析」按需取。**入口可见性保持宽松**：游戏屏判据只剩快照数（`turnSnapshots`；未知不藏功能），输入有无由点击时的解析内核判定并出声提示——与仓里既有模式一致（`TopBar` 注释原话「点击后再由 fetch 判定」）。

边界与代价：其一，v1.13 之前的快照与旧包**不回填**（输入没有别的可靠落点，logs 的对齐已知会错位——正是本裁决否掉「日志端点 + 猜对齐」的同一理由），那几幕点击后给「这一档没有留下当时的输入」；同理 `seq > 9999` 之后快照停写、重演会指向旧条目，文档化的已知边界。其二，游戏屏的回看是逐条本地单条查询，极端链在上限处降级提示，不无限回看。其三，files 相同的玩家回合现在会多落条目，history 比 v1.12 略胖（长世界本就是每回合三文件全文的量级；真正无新内容的回合仍被去重挡住）。被否决：**暴露 `GET /api/turnlog`** 走日志（要把「猜对齐」正式化成契约）、**服务端原子 `{action:"reroll"}`**（「目标幕/回退点」的规则要从客户端抄到服务端，两份规则是本仓最忌）、**不做**（刷新后重演永久不可用，且树屏的任意幕重演无从谈起）、**列表带 prompt**（把目录面变宽，而列表的所有消费者都不需要输入文本）、**导出时剥离 prompt**（导出/导入两种形态分裂 + 往返一圈的世界失掉重演能力）。
