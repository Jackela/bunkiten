# 世界线索引 schema 版本与启动迁移

`state/worlds/index.json` 此前是**裸数组**：形状只由 `server/worlds.mjs` 的 `readWorldsIndex` 隐式定义，文件里没有任何版本判据。后果是下一次结构改动只能靠「一次性特判」兜——仓库里已经躺着三处这种特判（`importWorld` 与 `importPresetBundle` 的 `version === 1` 硬等值、`src/lib/worlds.ts` 的 `isLegacyForkNote`、`worlds.mjs` 的 `migrateLegacyState`），而且每一处都只活在自己那条一次性路径上，没有统一的升级通道。裁决四件事。其一，**索引升成 `{ schema: 1, worlds: [...] }`**，`schema` 是整数、只由写路径维护；读路径**宽读两形态**（裸数组照收，`worlds` 数组才是真源，多出的顶层键忽略）——宽读是让迁移可以分两步走的唯一原因：先落骨架与断言、再翻写形态并接启动路径，中间任何一刻磁盘上的两种形态都能读。其二，**启动期一次性升级**：`migrateWorldsSchema(root)` 排在 `migrateLegacyState` **之后**（后者可能刚用新写形态建出索引，此时升级是 no-op），判据就是「顶层是不是数组」——是数组就原样包成版本化对象并返回 true（worlds 逐条不动、不补字段），已版本化、缺文件、坏 JSON 一律 false 且**不动笔**（宁可下次启动再试，也不覆写玩家索引）；幂等由判据本身成立，不靠标记位。其三，**永不绝收**：读路径不认识的高版本（`schema > 1`）照读不误，写路径**保留更高的 `schema` 与未知顶层键**（读-改-写，不覆写）——降级安装旧版客户端的玩家不该因此丢索引；只有「结构上无法升级」的形态才拒绝（如导出包里 `files.state` 为空——那是既有校验的语义，与本条无关）。其四，**导出包沿用同一策略**：`.world.json` 的版本闸从 `=== 1` 放宽成 `1..WORLD_BUNDLE_VERSION`，v1 包照收、按当前形状补齐（`forkedFrom: null`、不落 `fork.md`），`WORLD_BUNDLE_VERSION = 2` 起带血缘（见 ADR-0016 的包形态与 §5 的导出导入语义）。代价：其一，索引文件的形状从此是契约，改动要连带 `CONTEXT.md`、`AGENTS.md`、`docs/ARCHITECTURE.md` 与 `tests/server.test.ts` 的裸数组夹具（后者在迁移用例里被显式断言）；其二，写路径多一次读-改-写，坏 JSON 时按「当前进程已知的内容」重建（既有失败路径不变）；其三，`scripts/doctor.mjs` 的孤儿素材判定读全库 `state.md`，与索引形状解耦、不受影响。被否决：给三份引擎写的 md 加 YAML 版本头（改 SKILL 的状态文件格式、每轮重写都要保留头，代价远大于收益）、给 `history/NNNN.json` 条目加 `v` 键（`normalizeSnapshot` 已是唯一形状入口，收益最小）、`schema` 只写不判（等于没有迁移通道）、高版本索引直接拒读（降级即砖）。
