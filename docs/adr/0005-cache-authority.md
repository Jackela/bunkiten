# 缓存权威：规划只列新增，客户端兜底归一化，且变体必须一致

新章规划时，引擎先读 `assets/` 现状，制作清单只列尚不存在的项——缓存是权威，不重复生成。但引擎的判断可能漏（改名、大小写、空格、措辞差异），故客户端再做一层兜底：把清单项与 `assets/` 已有文件名做归一化比对（trim 后互为包含即视为已缓存），背景与立绘一视同仁地过滤。裁决的关键是「变体必须一致」：仅当归一化后的变体名也完全一致时才算命中，否则不认定已缓存。这条修的是既有「互相包含」匹配的 bug——旧逻辑下 `立绘-某角色.jpg` 的基础名会包含在 `立绘-某角色-微笑.jpg` 里，使差分项被基础立绘吞掉、永远不生成；要求变体一致后，差分/服装变体各自独立判断，缺哪张补哪张。
