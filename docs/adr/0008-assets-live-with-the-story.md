# 美术资产随故事走，不设全局素材池

裁决：立绘与背景一律写进所属剧本的目录 `presets/<presetId>/assets/<类型>-<名字>.jpg`（封面仍是同级 `presets/<id>/cover.jpg`），顶层 `assets/` 全局池删除。理由是三件事同时成立：其一，每个 preset 自带 `art_style`，美术天然属于「某个故事的美术」，混在一个池子里会让画廊串味、让缓存检查失去边界；其二，本次更名后的产品定位是「一个剧本 = 一个可分享/可删除的自包含文件夹」——把素材留在外面，导出/删除一个故事就会留下孤儿文件；其三，按剧本隔离后缓存规则变得平凡（引擎查当前剧本目录、客户端只清点该剧本），而旧的全局匹配必须靠「同名 = 复用」的脆弱约定维持。代价是同一角色出现在两个剧本时各存一份（否决了「全局池 + 名字前缀隔离」与「共享素材复制到各剧本」两种折中：前者违背自包含，后者让生成与清理产生隐藏耦合）。配套契约：`GET /api/assets` 必须带 `?preset=<id>`（缺失或非法 400）；`/img` 白名单只认 `presets/<id>/assets/<文件>.jpg` 与 `presets/<id>/cover.jpg`；服务端按提示词里的世界段嗅探「当前剧本 id」决定落盘目录，拿不到就不落盘（宁可晚落，也不写错故事）；老存档里的 `assets/<类型>-<名>.jpg` 由 `/img` 在**当前剧本目录**内兼容直服，其余情况返回 404——不做跨剧本扫描，避免把别人的素材迁进本故事。
