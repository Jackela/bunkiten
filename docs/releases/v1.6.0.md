# bunkiten v1.6.0

本版把「声音、后悔药、发版」三件事补齐：演出现在有 BGM / 环境音 / 音效（由作者在剧本里放素材，引擎按协议行点名播放），进度可以**精确回退到某一轮**（逐轮快照），发布流程变成「打 tag 即发版」；另有一轮体验补课（设置、世界线重命名与导出导入、画廊批量、剧情图降级与缩放、键盘操作）。

## 新功能

**音频**

- 协议头从 6 项扩到 9 项（`PROTOCOL_HEADS` 新增 `曲` / `环境` / `音效`）。三行都是演出指令、单独成段、不进正文：【曲】切换 BGM、`【曲】停` 淡出停止；【环境】切换环境音、`【环境】停`；【音效】是一次性音效（没有停止语义）。
- 素材由作者放在 `presets/<剧本 id>/audio/`，命名 `<类型>-<名>.<ext>`（类型 = `曲` / `环境` / `音效`，扩展名 = `mp3` / `ogg` / `m4a` / `wav` / `flac`）。引擎的播放指令**不携带路径**，只有名字，所以名对不上就是没有。
- 客户端 BGM 与环境音各一对音频元素交叉淡入（约 600ms），重复点同一首不重启；音效一次性、并发上限 4、带兜底超时释放槽位。**文件缺失、剧本没有 `audio/` 目录一律静默 no-op**——不报错、不打断剧情；引擎侧新增第 6 句规则（音频纪律），明确「绝不生成音频、绝不在标记里写路径」。
- 频率纪律：每轮【曲】/【环境】至多各 1 次，【音效】至多 2 次。

**设置（顶栏齿轮）**

- 主音量 + 静音 + 曲（BGM）/环境/音效三路滑杆 + 文本速度四档（慢 40ms / 标准 24ms / 快 12ms / 瞬间 = 一次显示全文）+ 自动前进（关 / 3 秒 / 5 秒，到点自动选第一条选项，倒计时显示在选项上方，你一动它就取消）。
- 设置存在本机 `localStorage`（键 `bunkiten.settings.v1`），逐键校验：存档损坏或某一键非法只回该键的默认值，不整份丢弃。

**逐轮快照与精确回退**

- 每个**正戏回合**结束后，把世界线的三份文件全文存进 `state/worlds/<worldId>/history/NNNN.json`（4 位递增、append-only；内容与上一条全等则跳过，不产生重复条目），同时记下节点 id 与章号。规划/美术/剧情/装配/创作模式这些非正戏回合不存。
- 新增 `GET /api/history?worldId=`（快照索引，升序）与 `?&seq=`（附三文件全文）。
- `POST /api/worlds {action:"restore"}`：先把当前状态自动写成一条 `backup` 快照，再覆盖成目标快照——覆盖的是**这条世界线**（三文件），随后客户端补发续档指令让引擎重新读档、恢复画面，**不是**从头重开。引擎正在写这一轮时不让回退（会提示等它这轮回完）。
- 剧情图上，有快照的节点会标注 `快照 #seq · 第 N 轮`，节点详情里出现「回退到此节点（原地）」，两步确认才执行。有快照的节点「在此分叉」也升级为**精确分叉**。

**世界线管理**

- `{action:"update"}` 支持显示名 `label`（≤60 字）与备注 `note`（≤200 字），空串即清除；列表优先显示 `label`，其次 `note`，都空则回退世界线 id。
- `GET /api/worlds/export?worldId=`：把一条世界线导出为 `<worldId>.world.json`（带 `Content-Disposition: attachment`），内含当前三文件与**全部逐轮快照**。
- `POST /api/worlds {action:"import", bundle}`：读回导出包（校验 `format: "bunkiten-world"` / `version: 1` / worldId 合法）；id 撞车不覆盖，自动排到 `<id>-2`、`<id>-3`…，并给新世界线补一条「（导入）」备注。

**画廊与剧情图**

- 画廊「选择模式」：勾选多张后批量重绘（顺序队列，一条画完才派下一条）或批量删除（两段确认；封面不受理删除，前端会明说）。
- 剧情图本章节点 > 40 个时默认降级为**列表**（可一键切回图形）；图形模式支持滚轮缩放（以指针为锚点）、拖拽平移、双击复位、`+` / `-` / `0` 快捷键，左下角显示缩放比例；节点支持方向键走位 + Enter 看详情。

**键盘**

- `1-9` 与 Numpad 直接选对应选项（焦点在输入框里时让路，不抢数字）；空格补全打字机（未在打字时不吞按键）。选项区与对话框都印了这两条提示。

## 契约变化

| 面 | 变化 |
|---|---|
| 协议头 | `PROTOCOL_HEADS` 6 → 9 项（+ `曲` `环境` `音效`），`isProtocolLine` 的正则由它构造；这 9 项与 server 各 `parse*`、SKILL 备忘、`docs/ARCHITECTURE.md` 表格四处一致，契约自检会断言 |
| 规则 | `RULES` 新增第 6 句（音频纪律，逐字副本见 `docs/ARCHITECTURE.md`）；`RULES[3]` 追加「可穿插【曲】/【环境】/【音效】切换音频」 |
| 新接口 | `GET /api/audio?preset=`（preset 必填且合法，否则 400）、`GET /audio?p=`（白名单 + `path.resolve` 前缀校验，同 `/img`；含长缓存）、`GET /api/history?worldId=[&seq=]`、`GET /api/worlds/export?worldId=` |
| 已有接口扩展 | `POST /api/worlds` 新增 `restore` / `update` / `import` 动作，`fork` 支持可选 `seq`；`POST /api/assets` 新增 `action:"delete"`（只受理 `assets/` 目录下的 `*.jpg` / `*.jpeg`，封面不受理，文件不存在 404） |
| SSE | 新增 `audio` 事件（`{type:"audio", kind, name}`），由客户端音频管理器消费 |

音频不落盘、不生成、不进 `assetRegistry`，`GET /api/assets` 不列音频——声音是**作者放进来的文件**，不是引擎产出物。

## 工程与发布

- **打 tag 即发版**：push 一个 `v*` tag（或手动触发）→ `.github/workflows/release.yml`。先跑 `guard`：校验 tag 必须等于 `v<package.json version>`（不等就秒级失败），并跑一遍 `npm test`（单测 + 集成，秒级；e2e 不进 CI）；通过后 mac / win 各自打包（一律 `--publish never`），最后由 release job 合并两平台校验和为 `SHA256SUMS.txt`（强制纯 LF）并建/更新 GitHub Release。
- **发布说明**：release job 优先用仓库里的 `docs/releases/<tag>.md` 当 Release notes（就是这份文件），没有才退回自动 notes。
- **签名与公证条件化**：仓库配了 `CSC_LINK` / `CSC_KEY_PASSWORD` 才自动发现证书签名，`APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `APPLE_TEAM_ID` 三件套齐全才提交公证（`afterSign` 钩子 `electron/notarize.cjs`，缺任一直接跳过，不 fail 构建）。未配 secrets 时显式 `CSC_IDENTITY_AUTO_DISCOVERY=false` 走未签名路径，构建照样成功。
- **自动更新**：打包态接入 electron-updater，启动时查一次新版本；开发态与 `--dir` 预检产物没有 `app-update.yml`，静默跳过。
- **新 script**：`npm run dist:mac:dir`（arm64 `.app` 目录，快速无签名预检，产物不含 `app-update.yml`）。
- **测试**：171 → **294 例**。单测 parser 65 / server 76 / crafting 52 / treeLayout 7 / ui 76，另有 `tests/integration/**` 集成层 18 例（假 ACP 引擎 + 真 `acp-server.mjs` 子进程、临时 game root / HOME / PORT，秒级覆盖图片落盘、目录穿越防护、音频索引与逐轮快照）。契约自检补进既有套件（协议头 9 项唯一真源 + 与 SKILL 一字不差的字符串快照）。
- **内部重构**：前端 store 从单文件拆成 `src/store/slices/*` 动作切片 + `src/store/{context,types,portrait}.ts`，行为不变。

## 安装说明

- **Windows**：下载 `Bunkiten Setup.exe`（安装版）或 portable 单文件版（免安装）。未签名，SmartScreen 会拦一下，选「仍要运行」。
- **macOS**：下载 `.dmg`（arm64 + x64 都有，按你的机器挑）或 `.zip`。**未签名**，第一次打开会被系统拦：在「应用程序」里**右键 → 打开** → 再点「打开」，只需做这一次。
- **自动更新限制**：**未签名的 mac 包不会自动更新**——macOS 的系统机制要求更新前后签名一致（Squirrel.Mac），签不上名的包装上去之后不会自己升级。当前 release 的签名/公证取决于仓库是否配置了证书 secrets：配了就是签名 + 公证（mac 包能自动更新），没配就是未签名，mac 上**要更新请重新下载安装包覆盖安装**——存档在游戏数据目录里，不会被覆盖安装清掉。
- 两种系统都需要本机已登录 grok CLI（`grok login`）；首次启动若提示未登录，按游戏里的引导处理，或看 [QUICKSTART.md](../../QUICKSTART.md)。
- 每个 release 附带 `SHA256SUMS.txt`，可用 `shasum -a 256 -c SHA256SUMS.txt`（Windows 侧 `certutil`/`Get-FileHash` 对照）校验下载产物。

## 升级须知

- **旧世界线照常能玩**：v1.6 之前建立的世界线没有逐轮快照，`history/` 会是空的。这些存档的剧情图不显示快照标注，节点详情里也没有「回退到此节点」；「在此分叉」自动走**旧的兼容路径**（复制当前三文件 + 写 `fork.md`，只回退进度指针、不推演）。想拿到快照，就在这个版本里继续玩——从下一次正戏回合结束开始正常落盘。
- **旧档资产路径只读兼容**（v1.5.1 起的规则不变）：老 state/标记里的 `assets/<类型>-<名>.jpg` 只在当前剧本目录内探测一次——命中直服、未命中 404，不跨剧本扫描、不迁移落盘。
- **音频**：旧剧本没有 `audio/` 目录 = 没有声音，一切照旧（不报错）。想要声音，按 `presets/<id>/audio/<类型>-<名>.<ext>` 放文件即可，不用改代码。
- **打包布局**：`presets/`、`.grok/` 与 `state/README.md` 在 asar 外的可写数据目录里（Windows 安装版 `…\Bunkiten\resources\game\`，macOS 包内 `Contents/Resources/game/`），开发模式则是项目根。所以自行放进 `presets/` 的剧本与音频文件不会被升级覆盖，世界线进度（`state/worlds/`，含 `history/`）也留在原地；删掉 `state/` 即重置进度（进度本身从不打包分发）。
