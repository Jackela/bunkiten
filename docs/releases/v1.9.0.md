# bunkiten v1.9.0

本版把 v1.8.0 之后欠下的账一次清完：**存档有了版本判据**（索引升成带 `schema` 的对象、启动期一次性迁移、旧导出包照收并按当前形状补齐），**舞台能同框两人**（发言者高亮 + 名牌、非发言者压暗，VN 的通行做法），**菜单交给 headless 原语**（↑↓/Home/End 走位与 typeahead 由 Radix 接管），**作者工具进了游戏**（`npm run doctor` 的判定搬到屏上），并把性能**测成了数字**——结论是不用虚拟化。旧存档与旧导出包直接用，无需任何手工迁移。

## 数据与存档

- **索引 schema（ADR-0018）**：`state/worlds/index.json` 从裸数组升成 `{ schema: 1, worlds: [...] }`。启动期在旧布局迁移之后跑一次 `migrateWorldsSchema`：裸数组升成版本化对象、条目逐条不动；已升级、缺文件、坏 JSON 一律不动笔（宁可下次启动再试）。**永不绝收**——读路径宽读两形态，`schema` 比当前新的索引照读，写路径读-改-写保留更高的 `schema` 与未知顶层键（降级安装旧版客户端不该丢索引）。
- **导出包 v2**：`.world.json` 现在带 `world.forkedFrom` 与 `world.forkMd`——导出再导入不再把分叉线在家谱里变成根。导入侧版本闸从「硬等值 1」放宽成 `1..2`：v1 包照收、按当前形状补齐（`forkedFrom: null`、不落 `fork.md`），坏值降级 `null` 而不整包拒绝——这就是「旧包 accept + upgrade」策略的落地样板。

## 舞台与演出

- **同屏多立绘（上限 2）**：`【立绘】<角色>|<变体>` 点名的角色现在各自占一席——队尾是发言者（全亮 + 竖排名牌），其余压暗缩小且不带名牌（Ren'Py 生态的 `focus=True/False` 约定）；第三人出场按队首淘汰，最近发言的两位留场，正好对上导演层的「聚光灯轮换」。让位分两档，1280×720 实测对话面板 732px、两人最左缘 765px > 面板右缘 746px。
- **背景交叉淡入**：换背景从硬切改成 600ms 双层淡入（新图预载完成才淡入、旧图留底），系统开了「减少动态效果」时瞬时切换。
- **立绘差分预热**：`【立绘】` 换差分不再「空白一下才画出来」——按剧本拉一次资产清单，命中角色的基础与全部差分都进预载，失败静默、不重拉。

## 无障碍

- **浮层语义补全**：两个抽屉 + 画廊大图预览 + 创作返回确认层拿到 `role="dialog"` / `aria-modal` / 可访问名、**焦点陷阱**（Tab 在层里回绕）与**关闭归还焦点**；层开着时背景整块 `inert`（键盘与读屏都逛不出去），画廊与创作屏的滚动容器同时上锁。
- **菜单迁移**：世界线行的 `⋯` 菜单迁到 `@radix-ui/react-dropdown-menu`（刻意不 portal——主题变量注入在 App 根，portal 到 body 会掉回兜底配色），↑↓/Home/End 走位与 typeahead 由原语负责，手写的三条监听全部删除。Esc 的属主仍是 App 一处。
- 顺带修好一条真行为：返回确认层开着时焦点不再停在输入框里，Esc 不再被「正在打字」豁免挡住。

## 作者工具与世界线

- **剧本体检屏**：`GET /api/presets/check?id=` 直出 `scripts/doctor.mjs` 的纯函数判定，屏上按组列出 `[ok]/[warn]/[error]` 与「N 项通过 · M 警告 · K 错误」摘要；标题屏角落簇进入，不必离开游戏去终端看报告。
- **世界线行缩略图**：行首 56×40 的剧本封面（复用 `/img` 白名单直服），没有封面的剧本退成同尺寸占位块——无破图、行高不变。
- 修掉标题屏「素材」在冷启动时会打开**空画廊**的问题（此前用的是 store 里可能为空的 `selected`）。

## 工程与验证

- **e2e 19 → 28 条**：新增同屏 2 立绘（几何 + 亮暗 + 名牌归属）、剧本体检屏、世界线 `⋯` 菜单键盘路径、家谱缩放、行缩略图、reduce 下换背景瞬时上屏、立绘预热不重复拉清单；spec 样板收进 `tests/e2e-ui/stack.ts`。
- **用例 415 → 447 例**（server 118 / crafting 56 / ui 136 / preload 8 / integration 29 …），契约 lint 与三份文档计数同批同步；覆盖率 lines 79.6。
- **性能实测（ROADMAP §6）**：画廊 300 张真实素材与剧情图 600 节点都在同一时间地板上（~820ms，dev 模式），服务端 `/api/assets`（500 素材 + 30 世界）8.1ms、`/api/worlds` 3.9ms —— 结论：当前规模**不需要虚拟化**，成本排序是图片解码/IO ≫ 布局与 DOM ≫ 纯函数。
