# bunkiten v1.13.0

这一版把三批一直没发的工作一次交付，主线三条：**多引擎后端（v1.11）**——引擎不再只认 grok，设置屏里可以切到 **Codex**（`codex-acp` 随包分发、玩家零安装，登录仍是你终端里那份 ChatGPT 登录态）；**渐进式披露（v1.12）**——命令轨从十项同权重平铺收成 5 个顶层分组，标题屏角落簇收成三枚可见 + 「更多 ▾」，菜单有了正经的键盘 Tab 走位，另有一批玩家侧小而准的功能（存档点命名、重绘带要求、剧情编辑按节点作用域）；**存档点重演（v1.13）**——「重演」不再只认刚走完的那一幕：剧情图里**任何一幕**都能退回去重发当时的输入，而且**你当时说的那句话随存档落盘**——刷新/重启，甚至换台机器导入回来，都照样能重演。

兼容性：旧存档、旧设置、已存凭据一律照旧；旧的世界线导出包（v1/v2）照收，只是那些快照没有留下输入——那几幕点击重演会给一句「这一档没有留下当时的输入」，不报错、不静默。

## 多引擎后端（v1.11，ADR-0022）

- **两个后端、一条 ACP 会话**：设置屏「引擎与密钥」顶部切换 grok（默认）/ Codex；差异全部收进描述符表——`shared/engines.mjs` 是展示真源（GUI 只渲染、不自带第二份表），`server/engines.mjs` 是行为真源（spawn / 注入 env / 规则与 skill 注入 / 档位形状 / 图片通道 / 登录登出），`server/acp.mjs` 不出现任何品牌字面量。
- **Codex 随包分发**：`scripts/stage-codex-acp.mjs` 把 `@agentclientprotocol/codex-acp` 及其依赖闭包（19 个包，含平台二进制，darwin-arm64 实测 ~290MB）按 `node_modules` 布局铺进 `build/codex-acp/`，`electron-builder.yml` 原样搬进 `resources/codex-acp/node_modules`——玩家不必另装 CLI。
- **登录是你的，游戏不碰**：Codex 会话跑在游戏自己的 `CODEX_HOME`（`~/.bunkiten/codex`，0700）里——`config.toml` 由游戏按当前规则重写（`developer_instructions` = RULES + skill 指引、`project_doc_max_bytes = 0` 关掉 AGENTS.md 注入、`skills.config` 指到落盘的 bunkiten skill），登录态从你的 `~/.codex/auth.json` **拷贝**复用（你重新登录就重拷、你登出就连副本一起删）；「登录 Codex」按钮走**随包** CLI 自己的 `login`，但 `CODEX_HOME` 指回你自己的 `~/.codex`——产物落在你终端也用的那份里，游戏不存任何东西（登出是全局的）。
- **档位形状两套**：grok 的 `set_config_option` 要 `{value:{value}}` 嵌套、codex 要裸字符串（`effortOption` 由描述符给）。断线续档 `.shell-session.json` 记 `{engine, sessionId}`：换引擎即弃用旧会话。
- **自备 key 仍只属于 grok**（Codex 的自定义服务是另一套接口协议）：切到 Codex 时对话组只留「沿用终端登录」，GUI 直接写明原因，而不是给一个点了会报错的输入框。
- 出图侧不变：图片自备 key 时两个后端都挂同一个 media MCP；`BUNKITEN_CODEX_ACP` / `BUNKITEN_CODEX_BIN` 仍是测试与自定义入口的覆盖开关。

## 渐进式披露与一轮收口（v1.12）

- **命令轨收成 5 个顶层**：设置（直达）｜回顾 ▾（历史 / 前情）｜图鉴 ▾（角色 / 画廊 / 剧情图）｜进度 ▾（重演这一幕 / 重开 / 换剧本）｜帮助——高频项一击可达，低频与破坏性项进二级菜单（此前十项同权重平铺，危险的「重开」还和常用项挤在一层）。菜单**非 portal、`modal={false}`**，保住主题变量；Tab 在菜单里前后走位、走到两端就把焦点交还页面（`src/lib/menuTab.ts` 一份规则，世界线行的 ⋯ 菜单与命令轨共用；**刻意不回绕**——菜单不该是键盘陷阱）。
- **标题屏角落簇收成三枚可见 + 「更多 ▾」**：素材 / 创作新剧本 / 设置留在外面（玩家真会用的），导出当前卡 / 导入剧本 / 剧本体检收进 `title-more` 菜单（v1.12 起的渐进式披露）；角落簇、轮播雪佛龙与「继续上次」一律只拦 Enter（← → 透传，焦点停在按钮上时键盘切卡不许失灵）。
- **存档点命名**：剧情图节点详情给存档点起个名字（≤40 字，存世界索引的 `snapshotLabels`，**不碰 append-only 的快照文件**），屏上标成「存档点 · 第 N 幕 · 名字」。
- **重绘带要求**：画廊预览里可以写一句要求（`美术：重绘 <类型> <名>：<玩家要求>`，≤200 字）——要求优先、身份锚点不减、与 `art_style` 冲突时以玩家为准；批量重绘恒为盲重绘。
- **剧情编辑按节点作用域**：`剧情：针对节点 <id>：<指令>`（只动该节点；id 找不到就按同章最接近的理解并说明），底部输入行仍是全树范围。
- **设置屏两层**：第一层主音量 / 静音 + 文本速度 / 自动前进；「细分音量」（曲 / 环境 / 音效）与「引擎与密钥」收进默认收起的披露里——从启动屏未登录态进来时自动展开。
- **打包态 e2e 跨平台**：`tests/helpers/packaged-app.mjs` 统一 macOS / Windows 的产物定位（8 例单测钉住三平台布局），Windows 侧由 CI 的 `packaged-win` job 真跑——「Windows 上的包真能开」第一次有了证据。

## 存档点重演（v1.13，ADR-0023）

问题：v1.7 起的「重演」把玩家输入只存在内存账本（`lastTurnPrompt`）里——刷新/重启后账本为空、入口形同虚设；而且它只认刚走完的那一幕，更早的任何一幕都重演不了。盘上的输入在 `logs/`，但日志的 seq 与快照**已知会错位**（快照去重、`restore` 的 backup、指令回合两边都不写），按 seq 去 join 等于把「猜对齐」做成契约。

- **输入随它产生的状态落盘**：`history/NNNN.json` 新增 `prompt`，只记**玩家输入**——客户端的开局/续玩指令回填空串（它们是客户端生成的指令、不是玩家的话；引擎侧原文仍在 `logs` 的 `prompt`，两处口径不同、各有其用）。关联天然（同一条目内），去重 / backup / 续玩那堆错位一次性消失。
- **去重改判据**：三文件与上一条全等**且这次没有新的玩家输入**才跳过——「玩家说了新话」永远落盘（三文件相同也是新的一幕，这是重演的地基）；空输入的读档回合只有真改了文件才落盘（不留噪声条目）。
- **两个入口、一套规则**：命令轨「进度 ▾ → 重演这一幕」（目标幕 = 盘上**最近一条带玩家输入的** turn 条目——刷新/重启后的「继续世界线」是空输入条目，会跳过它往回找，回看上限 8 条）与剧情图节点详情的「回到这一幕并重演」（目标幕 = 你点的那一条，两段确认、与回退同纪律）。回退点（该幕开演前的那一条快照）与输入由 `src/lib/replay.ts` 的两个纯函数判定，**两个入口共用同一份规则**，不写第二份。
- **时序不变（复用回退那条老路）**：退到目标幕开演前 → 补发续玩指令让引擎重读档 → 重同步收尾后自动重发当时的输入，可连演。
- **降级只给实话**：这是第一幕（无处可退）、旧档（没有留下输入）都经提示出声，不静默；**刷新/重启后照样可重演**（输入在盘上，不在内存）。
- **导出包 v2 → v3**：快照条目带 `prompt`——存档自洽，换台机器导入回来也能重演；v1/v2 包照收，缺字段的条目收敛为空串（那几幕给降级提示，不回填）。
- **顺带清的两笔账**：① 客户端 `parseWorldBundle` 的版本闸从「只认 v1」改成「版本是正整数，上限由服务端裁决」——此前 v1.8 起导出的 v2 包在应用内导入会被**本地**挡下（服务端明明已收）；② `lastTurnPrompt` / `pendingTurnPrompt` 两个内存账本字段整体删除。

## 工程与验证

- **用例口径**：单测 + 集成 **560+ 例**（实际 684），UI e2e **21 个 spec / 49 条**（新增「回到这一幕并重演」与「整页刷新后仍可重演」两条），契约 lint 与 README / AGENTS / ARCHITECTURE 同批同步；server 侧 `typecheck:server` 门禁照旧。
- **真引擎冒烟**（本机跑、不进 CI）：`npm run test:e2e` 三条——Grok 快速开局 2 回合、Grok 章节制作 3 回合、Codex 后端 1 回合。本轮按 lite 口径跑过 Grok 快速开局与 Codex 两条（Grok 走便宜档：`BUNKITEN_GROK_MODEL=grok-4.7-build-fast` + `EFFORT=low`），章节制作那条留给下一轮本机复跑（本文档的用法：改前端流程 / 协议后按需跑，会花真 token）。
- **新增测试面**：重演解析纯函数（`tests/replay.test.ts`）、快照 `prompt` 的形状/去重/往返/导入（`tests/server.test.ts` + `tests/integration/audio-history.test.ts`）、引擎描述符与 spawn 参数面（`tests/engines.test.ts`，含 `BUNKITEN_GROK_MODEL` 旋钮与既有的 codex 覆盖开关）。

## 已知限制

- **旧档那几幕不能重演**：v1.13 之前的快照没有 `prompt`，点击重演只会得到一句「这一档没有留下当时的输入」——输入没有别的可靠落点（日志的 seq 对齐已知会错位），刻意不做回填。
- **快照溢出**：`seq > 9999` 之后快照与回合日志都停写，此时重演会指向旧条目——文档化的边界（与 ADR-0009/0015 的既有取舍一致）。
- **真出图 opt-in 跑有代价**：需要本机已登录引擎 + 能出网 + 图片服务凭据，且**真的花一次对话与一张图**（「测试连接」的图片侧同理，GUI 里已明说）。
- **未签名的 mac 包不能自动更新**：Squirrel.Mac 要求新旧包签名一致，而本版发布的正是不签名产物（升级走手动下载 Release 产物）。要开签名见 [RELEASING.md](../RELEASING.md)；Windows 侧未签名只影响 SmartScreen 提示，不影响更新。
- **自备 key 明文落盘（v1.10 的刻意取舍）**：`~/.bunkiten/credentials.json` 是明文 + 0600，本机磁盘加密（FileVault / BitLocker）是这里的第一道防线；加密存储留给后续版本（见 ADR-0019 的「被否决的备选」）。
- **在线目录仍有窗口期**：目录更新是尽力而为的后台动作，窗口 ≈ `min(各发布源 CDN 缓存) + 6h + 一次抓取延迟`——不是实时；抓不到就继续用内置表，不影响任何已存凭据（ADR-0020）。
