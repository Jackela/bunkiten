# bunkiten v1.10.0

本版把「引擎用什么模型、用什么出图」从隐式的本机状态（`grok login` 的登录态、`~/.grok/config.toml`、shell 里的环境变量）搬进**设置屏里可配置、可验证、可撤销的两节表单**——填地址、密钥、模型，点「测试连接」真连一次，保存即时生效；不登录 grok 也能开玩。顺带修掉两个只有打包态才暴露的真 bug（**出图子进程起不来**、**引擎开局拿不到 bunkiten skill**），把服务目录变成**可随版本单独更新**的发布物，并把出图链路的 mock 覆盖铺到三层。旧存档、旧导出包、旧设置一律兼容，无需任何迁移。

## 引擎凭据进 GUI（ADR-0019）

- **设置屏「引擎与密钥」两节**：对话（LLM）与出图（图片）各一组，形态一致——**服务目录下拉**（27 条 + 「自定义」）、**地址 / 密钥 / 模型**三格、出图侧多一组尺寸（「尺寸」与「背景尺寸（高级）」，后者只对背景生效且优先）；密钥格 `type=password` + 「显示」切换，失焦即提交并回掩码。
- **服务目录**（`shared/providers.mjs`）：一张表同时喂 GUI 下拉与服务端校验，覆盖 OpenAI / Azure / Gemini / Mistral / OpenRouter / DeepSeek / Kimi / 智谱 / 百炼 / SiliconFlow / 火山方舟 / Groq / Together / Fireworks / xAI / 本机（Ollama、LM Studio）/ 自建与各家网关——凡说 OpenAI 兼容协议的服务开箱可用，长尾走「自定义」/ one-api / LiteLLM。不引 provider SDK，server 树保持零依赖。
- **「测试连接」真连一次**，不是 ping：对话侧拉 `{baseUrl}/models`（通了就不消耗生成额度，服务没这个端点才退化成一次最小对话）；**图片侧真的生成一张小图**——GUI 里明写了这一步会花一点钱。回延迟毫秒与失败原因（错误串已脱敏截断）。
- **保存即时生效 + 「立刻重启引擎」**：凭据是引擎子进程的 env，只在启动时读一次，所以生效路径就是重启会话；回合进行中拒绝重启（409，不截断正在落盘的那一幕）。
- **不登录也能玩**：对话侧走 grok CLI 自带的 BYOK 通道（`GROK_MODELS_BASE_URL` + `XAI_API_KEY` + `GROK_DEFAULT_MODEL`，「我们的值优先」地盖在进程 env 上）；首启屏因此是三态——有登录态照旧开玩、配好自备 key 也直接放行、两样都没有才给「填自备密钥」与终端 `grok login` 两个入口。图片侧没有这条通道，所以自建了一个零依赖的出图 MCP 工具（`generate_image`：prompt / 类型 / 名字 / 落盘路径），覆盖制作清单、首现背景、重绘三条出图路径。
- **凭据只落一处**：`~/.bunkiten/credentials.json`（目录 0700 / 文件 0600、临时文件 + rename 原子写）。**永不明文出口**——HTTP 响应只有掩码视图（`sk-…4f2a`），日志、逐轮快照、回合日志、世界线/剧本导出包、SSE 事件里都没有明文，明文只活在磁盘与「你正在输入」的那一帧。

## 打包态的两个真 bug

- **出图修好（`asarUnpack` 整树）**：MCP server 是被引擎拉起的**子进程**，子进程读不了 asar——此前只解了 `media-mcp.mjs` 一个文件，它相对 import 的兄弟（`config.mjs`/`assets.mjs`/`presets.mjs`/`credentials.mjs` 与 `shared/*`）都不在 unpacked 树里，打包态一调就 `ERR_MODULE_NOT_FOUND`，表现是**出图静默不工作**（正文与选项照旧，只是没有图）。现在 `electron-builder.yml` 的 `asarUnpack` 覆盖 `server/**` 与 `shared/**` **两整棵树**，运行期再把路径里的 `app.asar` 段换成 `app.asar.unpacked`。
- **打包冒烟新增 MCP 握手断言**：`tests/e2e-packaged/` 里让假引擎真的把 MCP 子进程拉起来跑一遍 `initialize` → `tools/list`——这条断言就是上面那个 bug 的门禁，从此「打包态出图静默坏掉」不会再靠玩家发现。
- **引擎 skill 注入（ADR-0021）**：spawn 现在固定带 `--plugin-dir <gameRoot>/.grok`。原因是一个实测事实：项目级 skill（`.grok/skills/bunkiten/SKILL.md`）受 grok CLI 的**文件夹信任**门控，而两个 game root（开发态 = 仓库根、打包态 = `resources/game`）都未被信托——`grok inspect --json` 回 `projectTrusted=false`，skills reminder 里根本没有 bunkiten，纪律的生效全押在「模型会不会自己翻到那个文件」。`--plugin-dir` 是会话级、always trusted 的注入通道：不看也不改你的全局信任文件，加了这个 flag 引擎开局就拿到 bunkiten skill——**开发态与打包态都生效**（指向不存在/空目录无害，集成 harness 的临时 game root 就没有 `.grok`）。
- **出图工具名容错**：`tools/call` 现在同时接受裸名 `generate_image` 与 catalog 全名 `bunkiten-media__generate_image`——真引擎经 `search_tool`/`use_tool` 发的是后者，此前只认裸名会被回成「未知工具」，出图同样静默变成没图。

## 服务目录可在线更新（ADR-0020）

服务目录原先只是打进包里的死数据，新服务或某家改了地址就得等下一个游戏版本。现在链路是「仓库 JSON 发布源 → 服务端启动抓取 → 本地缓存 → 内置兜底」：

- **发布源**：仓库里的 `docs/providers.json`，由 `npm run providers:export` 从唯一真源（`shared/providers.mjs`）生成，**只搬不改**——手改 JSON 会被契约 lint 挡下，不存在第二份目录。
- **抓取与缓存**：服务端启动时**非阻塞**抓一次（主源 jsDelivr、备源 GitHub raw，单次 10s 上限、失败静默），落到 `~/.bunkiten/providers.json`（与凭据同目录，0700/0600，**24h TTL** 节流）；读路径按 远端 → 缓存 → 内置 三级回落。
- **远端新增的服务商现在能直接选中保存**：服务端凭据校验的 provider 白名单从「内置表」放宽成 **内置 ∪ 当前目录**——下拉里选得到的必须存得下（否则就是「能选不能存」）；反过来，目录暂时抓不到时，你已经存下的远端服务商不会被静默改写。
- **安全边界逐条钉住**：远端**只喂下拉候选**，绝不据此改写你已存的地址与密钥；发布源里的地址只收 `https`（例外只有本机 `localhost`/`127.0.0.1`）；校验失败**整包即弃**（不动缓存、不更 memo）；只搬白名单字段（远端多出的键一律丢掉）。单条坏条目只丢那一条，不牵连整份目录。
- **设置屏**：下拉优先吃在线目录，`source` 不是「内置」时标一行「在线目录」，让你知道候选比随包那份新；读不到就静默回落内置真源——回落是正常路径，不报错、不打日志。

## 稳定性

- **启动链不再无限转圈**：三条读接口（`/api/auth`、凭据视图、服务目录）加了显式超时——卡住会落到首启屏与设置屏**既有的**错误态与重试入口，而不是永远等下去。
- **测试栈就绪判据改验经代理的 `/api/auth`**：此前等的是进程端口，vite 代理还没接上就开始跑，属于时序侥幸。
- **e2e 冷启动预算分账**：把「冷启动打包成本」与「用例自身等待」拆开记账，根治「世界线屏 ↑↓」的偶发红；**焦点归还加固**根治 game 屏 Tab 的偶发红（浮层关闭后焦点归属不再依赖时序）。

## 工程与验证

- **mock 出图链路三层覆盖**（都不需要真凭据、真网络）：集成层 + e2e-ui 层**随 CI 跑**，打包态一层 opt-in——上面那两个打包态 bug 都在这套覆盖里有对应断言。
- **真链路仍 opt-in**：`tests/e2e-packaged/real-image.spec.ts` 需要真 grok CLI + 真图片服务 + 出网 + 凭据，默认不跑（见下方「已知限制」）。
- **用例口径**：单测 + 集成 **560+ 例**（实际 589），UI e2e **21 个 spec / 44 条**；契约 lint（协议常量真源断言、发布源与真源深等、GUI 不许自带第二份服务表）同批同步。

## 已知限制

- **真出图 opt-in 跑有代价**：需要本机已登录 grok CLI + 能出网 + 图片服务凭据，且**真的花一次对话与一张图**（「测试连接」的图片侧同理，GUI 里已明说）。
- **在线目录有窗口期**：CDN 边缘缓存 + 24h TTL，远端改动到你这边的延迟最多一天 + 缓存时间——不是实时。
- **Anthropic 原生协议经本通道支持不了**：CLI 的 `api_backend` 只能写在 `~/.grok/config.toml` 的 `[model.*]` 里，env 通道给不了（已实证请求照走 `chat/completions`）。要用 Anthropic 就走它的**兼容网关**（「自定义」/ one-api / LiteLLM）。
